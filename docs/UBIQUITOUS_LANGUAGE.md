# Ubiquitous Language

The following terms are the canonical graph vocabulary for the Evidence-Gated Planning Provenance Harness. Graph nodes, graph validators, graph reports, and graph docs should use these terms when they describe graph responsibilities.

This is not a ban on normal repo language. Runtime statuses, schema field names, provenance levels, command names, and existing harness terms such as `CERTIFIED_DONE`, `policy_engine`, `verifier_provenance`, and `artifact_tests` remain valid where they are the exact machine contract.

| Term | Description |
|------|-------------|
| **Goal** | The raw user-provided objective. |
| **Goal Contract** | Formalized contract derived from the Goal, containing constraints and success criteria. |
| **Constraint** | A restriction that must be satisfied by any selected plan. |
| **Success Criteria** | Concrete, measurable outcomes that indicate the Goal has been achieved. |
| **Plan Seed** | High-level strategy derived from the contract, without concrete executable steps. |
| **Plan Candidate** | A concrete plan derived from the seed, containing expected outputs, tool requirements, risk notes, and a verifier path. |
| **Candidate Evaluation** | The process of applying risk, tool, and verification checks to a candidate. |
| **Risk Check** | Assessment of potential failure modes for a candidate. |
| **Tool Check** | Verification that all required tools are available for the candidate. |
| **Verify Check** | Execution of the candidate’s verifier to ensure output correctness. |
| **Applicability Gate** | Decision node that selects a single candidate based on evaluation results. |
| **Selected Plan** | The candidate approved by the applicability gate; it drives execution but does not certify. |
| **Milestone Plan** | High‑level decomposition of the selected plan into milestones. |
| **Local Step Plan** | Detailed steps for a single milestone. |
| **Merged Plan** | The fully‑expanded execution plan derived from all local steps. |
| **Task Graph** | Directed acyclic graph of executable tasks, their IDs, actions, and artifact dependencies. |
| **Artifact Graph** | Graph of produced artifacts, their producers, paths, and hashes. |
| **Verifier Graph** | Graph linking each artifact to its verifier evidence (provenance level, strength). |
| **Policy Decision** | Provenance‑aware policy evaluation that judges verifier evidence and decides a status. |
| **Certification** | Authoritative record of the final status, written by the certifier. |
| **Pi Report** | Read‑only report generated by Pi that reflects the certification without altering it. |
| **Monitor Verdict** | Outcome of the monitoring subsystem (e.g., MONITOR_PASS, MONITOR_FAIL). |

Critical distinctions:

```text
MONITOR_PASS != TASK_DONE
ARTIFACT_EXISTS != GOAL_SATISFIED
SELECTED_PLAN != CORRECT_PLAN
VERIFIER_EXISTS != CERTIFYING_VERIFIER
PI_REPORT != CERTIFICATION
```

Use these terms as the graph language. Do not use them to upgrade evidence, policy, or final status.
